## 2. 缺陷详情

### A1 · OpenAI 缓存 token 重复计费 【已复现】

- 位置：`internal/proxy/sse.go:204-215`（流式）、`internal/proxy/sse.go:241-251`（非流式）、`internal/pricing/pricing.go:62-65`
- 原因：OpenAI 的 `prompt_tokens` **本身包含** `prompt_tokens_details.cached_tokens`，代码却同时写入 `Input = prompt_tokens` 和 `CacheRead = cached_tokens`，计价时各乘一次单价。
- 复现：`prompt=1000, cached=800, out=10`，单价「输入 1 / 缓存读 0.1 / 输出 1」美元每百万
  - 当前结果：`Input=1000 + CacheRead=800 = 1800 > prompt_tokens=1000`
  - 当前成本：0.00109，正确应为 0.00029
- 附带影响：`record.Input` 虚高，缓存命中率分母失真。
- 修复方向：解析时从 `Input` 中扣除 `cached_tokens`（与 Anthropic 语义对齐），或在计价时对 OpenAI 格式做区分。前者更简单，且能与 A5 一并解决。

### A2 · SSE 末帧无换行被丢弃 【已复现】

- 位置：`internal/proxy/sse.go:75-113`
- 原因：`FeedChunk` 只在遇到 `\n` 时提交行，流结束时缓冲区内容从不提交，也没有 `Flush()/Close()` 收尾。
- 复现：`data: {...message_start...}\n` + `data: {...message_delta, output_tokens:55}`（无结尾换行）→ `Input=77 Output=0`（应为 77/55）
- 触发：上游最后一帧后直接 EOF。不少自建/中转服务如此。
- 修复方向：新增 `Finish()` 方法，流读取循环结束后调用一次，提交残留行。

### A3 · `/v1/responses` 用量完全不解析 【已复现】

- 位置：`internal/proxy/sse.go:196-252`
- 原因：Responses API 用 `input_tokens` / `output_tokens` / `input_tokens_details.cached_tokens`，两种解析器只认 `prompt_tokens` / `completion_tokens`。
- 复现：`{"usage":{"input_tokens":100,"output_tokens":50}}` → `{Input:0 Output:0 CacheRead:0 CacheCreate:0}`
- 说明：`handler.go:82` 的 `classify` 明确把 `/v1/responses` 归为受支持的 openai 路径。
- 修复方向：`oUsage` 增加两组字段并做优先级回退。

### A4 · 峰谷按「响应结束」时刻计价 【代码确认】

- 位置：`internal/proxy/handler.go:521`（`Ts: time.Now().Unix()`）、`internal/stats/recorder.go:88`
- 原因：`record()` 在响应处理完毕后调用，`Ts` 是结束时刻。长流跨峰谷边界时按错误档位计价。
- 修复方向：用请求开始时刻（`ServeHTTP` 的 `start`）作为记录时间戳。

### A5 · 流式/非流式对 `cache_read_input_tokens` 不一致 【已复现】

- 位置：`internal/proxy/sse.go:213-215` vs `241-251`
- 原因：流式解析器认部分中转的 Anthropic 风格字段 `cache_read_input_tokens`，`ParseNonStream` 不认。
- 复现：同一响应，流式缓存读 80，非流式 0。

### A6 · `parseNum` 非数字静默返回 0 【已复现】

- 位置：`internal/pricing/pricing.go:179`
- 原因：`fmt.Sscanf(s, "%g", &f)` 失败时 `f` 保持 0，无任何报错。
- 影响：导入带 `$`、千分位逗号的定价文件 → 全部变成 0 定价。
- 修复方向：返回 `(float64, error)`，导入时汇总失败项并回报。

### A7 · 定价键精确匹配 【已复现】

- 位置：`internal/pricing/pricing.go:51-56`
- 原因：`p.prices[model]` 精确匹配，上游模型名与定价键存在大小写或空格差异时静默 $0。
- 修复方向：存取两侧统一 `TrimSpace` + 小写，或加显式的不匹配告警。

### B1 · SSE 错误事件永远抓不到 【已复现】

- 位置：`internal/proxy/sse.go:116-128`（关键在 118 行）
- 原因：错误检测在 `sseData()` **之前**对整行 `json.Unmarshal`，而真实 SSE 行是 `data: {...}`，整行不是合法 JSON，必然失败。且 OpenAI 形态 `{"error":{...}}` 不含 `"type":"error"`。
- 复现：`event: error\ndata: {"type":"error","error":{...}}\n\n` → `ErrMsg=""`，统计 `OK=true`
- 后果：**监控全绿但客户端拿到的是错误流**。这是最危险的一条。
- 修复方向：先 `sseData()` 取 payload 再判定；同时支持 `type:error` 与 `error` 顶层字段两种形态。

### B2 · 流读取错误只 break 不置 errMsg 【代码确认】

- 位置：`internal/proxy/handler.go:294-309`
- 原因：`upBody.Read` 返回错误时直接 `break`，上半截已转发，但 `errMsg` 仍为空。
- 后果：上游中途掉线被记为 `OK=true err=""`，与正常请求无法区分。
- 修复方向：`readErr` 非 EOF 时写入 `errMsg`。

### B3 · Flusher 断言失败静默忽略 【代码核实】

- 位置：`internal/proxy/handler.go:291`
- 原因：`flusher, _ := w.(http.Flusher)` 失败时静默。Wails 的 `contentTypeSniffer` 包装器没有 `Flush` 方法。
- 后果：桌面模式下 SSE 不逐帧下发，且无任何日志。

### B4 · 解析不出 model 直接 502 【已复现】

- 位置：`internal/rewrite/rewrite.go:40-46` + `internal/proxy/handler.go:214-219`
- 原因：`Extract` 注释写明「解析失败返回 Root=false，**调用方按透传处理**」，但 handler 直接拿 `info.Model=""` 去 `Decide`，所有通道都需要非空模型名 → 链为空 → 502。
- 复现：空体、`{}`、`model:""`、`model:null`、非法 JSON、`GET /v1/files` 全部 502，上游命中 **0 次**。
- 附带：错误信息「请先添加供应商并配置路由」具有误导性。
- 修复方向：`Root == false` 时走「默认供应商透传」分支，不依赖模型名。

### B5 · `resolve` 不校验协议端点 【已复现】

- 位置：`internal/routing/routing.go:127-149`、`internal/proxy/handler.go:236-247`
- 原因：`resolve` 只校验「启用 + 有 Key + 有模型」，不校验该 format 对应的 URL。`buildUpstreamRequest` 报错后只 `continue` 到链上下一目标，而默认供应商不在链里。
- 复现：只配 OpenAI 端点的供应商，anthropic 请求仍被选中 → 502。
- 修复方向：`resolve` 增加 format 参数并校验对应 URL；无可用端点时视为不可解析。

### B6 · 404 不触发切换 【代码确认】

- 位置：`internal/proxy/handler.go:435-443`
- 原因：`shouldFailover` 只认 429/402/403/408 与可选 5xx，404 不切换。
- 触发：同名供应商模型池为空 → 上游返回 404，链里其实还有可用的 B，但客户端直接拿到 404。
- 修复方向：same_name 模式下把 404 纳入切换条件（manual 模式可配置）。

### B7 · `isSSE` 大小写敏感且只认 200 【代码确认】

- 位置：`internal/proxy/handler.go:494-497`
- 原因：`strings.Contains(ct, "text/event-stream")` 对 `Text/Event-Stream` 不匹配；且 `resp.StatusCode == 200` 排除了 201。
- 后果：被当作非流式整段缓冲，真实长流会在 32MB 上限处 502。

### B8 · 轻量通道多目标不顺延 【已复现】

- 位置：`internal/routing/routing.go:117-124`（`firstTarget`）
- 复现：配置 2 个 target，决策链长度 = 1。
- README 原文：「命中触发条件的请求按列表顺序转发：首目标承接全部流量，失败/限额时顺延下一目标。」
- 修复方向：`firstTarget` 改为返回全部可解析目标，按序进入切换链。

### B9 · 错标 deflate 回退失败 → 502 【代码确认】

- 位置：`internal/proxy/handler.go:378-390`
- 原因：`zlib.NewReader` 失败后回退裸 `flate`，但不对裸流做校验，首次 `Read` 才报错，且前缀已丢弃。
- 后果：返回 502，而非注释承诺的「原样透传」；流式则为半截乱码。

### B10 · `include_usage` 未生效时用量恒 0 且无提示 【代码确认】

- 位置：`internal/proxy/sse.go:196-216`
- 原因：上游忽略 `stream_options.include_usage` 时，流里没有 usage 帧，用量全 0，无任何告警。
- 修复方向：流结束且 usage 全 0 时记录一条诊断（日志或统计字段）。

### C1 ⚠️ · 归档 seq 仅进程内唯一 【已完整复现】

- 位置：`internal/archive/archive.go:114-131`、`internal/store/store.go:561-586`
- 原因：**上一轮的修复只覆盖进程内**。`lastSeq` 是内存 map，重启后清空，`seq` 回到 `snap.Ts`。
- 完整复现（`probe_restart3`）：
  ```
  首次运行: id=1 seq=1000 / id=2 seq=1001 / id=3 seq=1002
  重启后:   id=6 seq=1002  ← 与 id=3 撞号，文件被覆盖
  裁剪后:   id=5 seq=1001 *** 文件缺失 ***
  ```
- 后果：元数据还在、文件没了 → UI 打开该快照直接 500；两个时间点显示同一份内容。
- 修复方向：**seq 不应用时间戳**。改为「写入时查询该会话当前最大 seq + 1」，或直接用数据库自增 id 作为文件名。

### C2 · `testAllProviders` 切片头数据竞争 【代码确认】

- 位置：`internal/api/handlers.go:319-336`
- 原因：主 goroutine 在循环里 `items = append(items, ...)` 写切片头，已启动的 goroutine 同时执行 `items[idx].res = res` 读切片头。`mu` 只保护元素写入，不保护切片头。
- 后果：`append` 扩容后，早先 goroutine 可能写进旧底层数组，结果丢失；随后 `if it.res == nil { continue }` 静默跳过 → 「测试全部」返回数量和持久化结果都缺项，前端仍提示全部正常。
- 修复方向：先构造定长切片（或先算好数量 `make([]item, n)`），再启动 goroutine。

### C3 · `GroupBy` 的 `ORDER BY cost` 不是按总费用 【已复现】

- 位置：`internal/store/store.go:345-349`
- 原因：聚合查询里的裸列 `cost` 取任意一行的值，不是 `SUM(cost)`。
- 复现：A 组 100 条共 $1.00，B 组 1 条 $0.50 → **B 排在 A 前**。
- 修复方向：`ORDER BY SUM(cost) DESC`。

### C4 · 设置保存丢失其他页面修改 【已复现】

- 位置：`internal/api/handlers.go:422-444`
- 原因：`PUT /admin/settings` 是整体替换；设置页与路由页各自在 `mounted` 拉快照，后保存者覆盖先保存者。
- 复现：A 页保存「注入守则」→ B 页（旧快照）只改轻量开关并保存 → A 的守则被清空。
- 影响面：路由页每个 Toggle、每个别名输入都会触发 `putSettings`。
- 修复方向：改为字段级合并（指针/PATCH 语义），或引入 `updated_at` 版本号做乐观锁。

### C5 ⚠️ · 卡片与曲线统计窗口不一致 【已复现】

- 位置：`internal/api/handlers.go:109-115`

### C6 · `Cfg()` 浅拷贝共享底层数组 【已复现】

### C7 · 最小化还原白屏，无法自救 【源码确认】

- 位置：`main_desktop.go:84-89`

### C8 · 非法端口锁死桌面版 【已复现】

## 4. 审计覆盖与已知限制

### 已核查确认**没有问题**的方向

**转发/SSE**
- SSE 跨 chunk 边界：按行缓冲，1–64 字节任意切分均正确（末行无换行除外，见 A2）
- 客户端断开后上游关闭：由 `r.Context()` 驱动，实测 100ms 内关闭
- 切换不重复计费：200 永不切换，失败体已排空并关闭
- 改写精度：`map[string]json.RawMessage` 逐字节保留，无 float 精度损失
- Anthropic system 注入：只追加末尾，不破坏 `cache_control` 断点
- OpenAI `content: null`：已显式处理
- `message_start`/`message_delta` 合并：Input 覆盖、Output 取 max，不翻倍
- `/v1/models` 鉴权：与转发同一前置校验，不可绕过
- gzip / 裸 deflate 解压与失败回放：正确（错标情形见 B9）
- same_name 模型匹配：按上游真实模型名比较，方向正确（问题仅在 404 不切换，见 B6）

**计价**
- 跨午夜、分钟精度、end 不含、峰优先于谷、倍率：均正确且有测试

**存储**
- `daily_stats` 与 `requests` 同事务；清理明细后聚合仍在
- 成本在消费时按请求时刻算一次，改价不重算（符合 README）

- `listRequests` 的 offset 可用；`deleteSession` 对正常 key 删除彻底、sanitize 与归档侧等价

**前端**
- 路由切换会重挂载并重拉，无陈旧数据
- 保存后均 `load()` 重拉；轮换密钥立即更新展示
- 编辑供应商留空 `api_key` 不覆盖旧密文
- 后端已把 null 归一化为 `[]`，前端 push/splice 安全

## 6. 验证方式约定

修每批时的硬性要求：

1. **先写失败测试**，确认在修复前确实失败（回退验证），再改实现。
2. 每条修复必须附带一个精确断言的用例，例如 A1：
   ```go
   // prompt=1000, cached=800, 输出 10, 输入单价 1, 缓存读 0.1
   // 必须得到 0.00029, 而不是 0.00109
   ```
3. 全量 `go build ./... && go vet ./... && gofmt -l && go test ./... -count=1` 通过。
4. CI 四个 job 全绿后再合并。
5. 每批独立发一个 preview 版本，便于用户按批验证。
